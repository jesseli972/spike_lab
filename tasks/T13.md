# T13: Validate and tune

Read `CLAUDE.md` before starting.

**Goal:** prove the physics behaves sensibly, and tune the presets until each one lands in.

**Files:** `tests/scenarios.test.js`, `docs/validation.md`, `src/ui/presets.js`. **Needs:** T11.

Starting presets (speed shown in km/h; store it in m/s):

| Preset | Contact (x, y, z) | Speed | Aim | Vertical | Spin |
| --- | --- | --- | --- | --- | --- |
| Float serve | (−9.5, 2.6, 0) | 65 km/h | 0° | 12° | none |
| Jump topspin serve | (−9.0, 3.1, 0) | 95 km/h | 0° | 4° | top, 360 rpm |
| Outside spike | (−1.5, 3.2, −3.0) | 80 km/h | 20° | −17° | top, 300 rpm |

1. Write scenario tests using `simulate`:
   - The same launch with topspin lands at least 1 m shorter than with no spin.
   - The same launch with backspin lands farther than with no spin.
   - Raising speed by 10% on a serve that is in makes it land farther.
   - Every preset ends `'in'` with net clearance between 0.05 and 1.0 m.
2. If a preset fails, change only its vertical angle (in 1° steps) and speed (in 2 km/h steps) until it passes.
3. Check whether the panel's default values land in. If not, report values that do.
4. Write `docs/validation.md`: one table with each scenario, its inputs, landing point, flight time, net clearance, and pass or fail.

**Done when:**

- All scenario tests pass.
- `docs/validation.md` lists every scenario and the final preset values.

**Watch out:** never change a physics constant or a physics file to make a test pass. If the physics looks wrong, report it under QUESTIONS.
